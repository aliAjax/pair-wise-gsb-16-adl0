# hxwl-01 听力验配修订台账

门店听力师的验配台账：解决前班只在纸上改写、左右耳增益与反馈等级变化说不清的问题。

## 业务规则

- **初配录单**：客户编号、姓名、耳别、助听器（品牌/型号/机身编号）、气导/骨导听力数据、言语识别率、初配增益与反馈等级。
- **复调带单**：发起复调自动带出上一确认单的双耳各频率增益与反馈等级，并实时显示与上次的差值。
- **强制写原因**：任一频率增益变化 **超过 6dB（|Δ| > 6）**，或反馈等级**升高**，必须填写改动原因才能确认。
- **旧单不可覆盖**：复调确认后只在修订链尾部追加下一编号（revNo 1 → 2 → 3…），历史确认单只读保留。
- **同耳草稿唯一**：同一客户同一耳只保留一份待确认复调草稿（按 `客户编号::耳别` 索引，覆盖式自动保存）。
- **草稿不串台**：初配草稿按独立 draftId 存储；复调草稿以客户+耳别为键，换单编辑器整体换挂。
- **重开可查**：数据存 localStorage，刷新/重开页面可按客户编号、姓名和耳别查找并续填草稿。

## 分层结构（资料 / 校验 / 存储分离）

```
src/
├── domain/            # 资料层：类型、常量、纯领域函数、示例数据
│   ├── constants.ts   # 频率点、耳别、反馈等级、限值
│   ├── types.ts       # FittingChain / FittingRevision / 草稿类型
│   ├── model.ts       # 链键、增益差值、修订构造、空白表单（纯函数）
│   └── seed.ts        # 示例台账
├── validation/
│   └── validate.ts    # 校验层：数值解析、限值、6dB/反馈升高规则（纯函数）
├── storage/
│   └── storage.ts     # 存储层：localStorage 分键读写 + 结构校验
├── state/
│   └── useLedger.ts   # 状态编排：确认追加、草稿唯一性、持久化触发
└── components/        # UI（侧边栏、详情、修订链、复调/初配编辑器、看板）
```

存储键互不覆盖：

- `fitting-ledger:chains:v1`（已确认台账）
- `fitting-ledger:drafts:adjustment:v1`（复调草稿）
- `fitting-ledger:drafts:initial:v1`（初配草稿）
